# Нямыч — HR-ассистент сети «Вкусный Дом»

AI-ассистент, который отвечает сотрудникам на вопросы о регламентах, процедурах
и стандартах сервиса — на основе базы знаний компании, с указанием
документа-источника в каждом ответе.

Работает в двух каналах с одним и тем же «мозгом»: **Telegram-бот** и
**веб-виджет** на внутреннем портале компании.

---

## Что внутри

```
├── site/               — внутренний портал (index.html, статический сайт)
├── knowledge_base/      — 22 документа базы знаний (политики, процедуры,
│                          стандарты сервиса, FAQ)
└── n8n_workflows/        — экспортированные workflow'ы n8n (бэкап/история)
    ├── Нямыч___HR-ассистент_Вкусный_Дом.json   — основной RAG-чат
    │                                              (Telegram + веб-вход)
    └── Qdrant.json                              — индексация базы знаний
```

## Как это устроено

1. Сотрудник задаёт вопрос — в Telegram-боте или в чат-виджете на сайте.
  
2. Ассистент ищет подходящий фрагмент в базе знаний (22 документа) и
   формулирует ответ понятным языком.
3. Каждый ответ содержит ссылку на документ-источник. Если ответа в базе
   нет — Нямыч честно об этом скажет и направит к HR, а не придумает.

Сайт дополнительно умеет:
- показывать полный текст любого документа по клику (модальное окно);
- подтягивать новости компании и «Сотрудника месяца» из базы данных
  (NocoDB) — редактируются без правки кода сайта.

## Инфраструктура

| Компонент | Где |
|---|---|
| Веб-портал |  статический хостинг через Dokploy |
| Оркестрация и логика ассистента | n8n (self-hosted) |
| Хранилище контента (новости, сотрудник месяца, логи) | NocoDB |
| Векторный поиск по базе знаний | Qdrant |
| Доступ к языковой модели | через прокси-сервис |

## Деплой

Сайт разворачивается автоматически из папки `site/` через Dokploy при
каждом пуше в ветку `main` (Build Path: `/site`, тип — Static).

## Документы базы знаний

Полный список и структура — в `knowledge_base/`, по разделам:
`01_общая_информация`, `02_политики`, `03_процедуры`, `04_стандарты_сервиса`,
`05_faq`. У каждого документа есть поле «Дата актуализации» — при
изменениях в законодательстве или регламентах компании документ нужно
обновить и актуализировать эту дату.
